# SubRotato

(Named Sub Rotator until 2026-10-19. Internal ids keep the old name so saved data and saved plan files still open: the storage key `subrotator:v1`, the file data mark `subrotator-plan` and `app: "sub-rotator"`, the project folder.)

Free, no-login web tool. Pick your streaming and gaming subscriptions, list what you want to watch or play, and it plans the cheapest month-by-month rotation (pay for one service at a time). Mobile-first. Goal: small, fun, useful to a lot of people, easy to share.

Read HANDOFF.md for current state, next steps, and what the owner still has to provide.

## Code conventions
- Countries: US (the base catalog, unchanged), CA, GB, AU, MX. `COUNTRY` comes from `?country=GB` (kept in localStorage `subrotator:country`), else the saved plan's `country`, else the browser region, else the time zone; the country menu on Services reloads the page. `applyCountry` rewrites `CATALOG`, `FAMS`, `YEARLY`, `TRIALS`, `BUNDLES` and the statement `FAMILIES` in place from `COUNTRY_DATA` (local prices and price options, local services such as Crave, NOW, ITVX, Stan, Binge, Kayo; `homes` say where a US service's shows stream, HBO on Crave in Canada). Money goes through `money0`/`money2` (`CI.cur`, no cents in pesos); money thresholds scale by `CI.fx`. Never hard-code "$" in text. `state.country` is saved (a save with no country is a US plan); moving country re-prices (your own services convert by `fx`), moves the titles of a service not sold there to its home there, or sets it aside in `state.away` until a country sells it again, and says so once. A plan file from another country is checked, opens in that country, and keeps yours in `subrotator:before-open` for Undo. The country menu changes only on its Change button. Sports seasons show only in the US. Statements use the country's date order (`dmy`) and read Spanish month names.
- Spanish: every English text a person sees has its Spanish one beside it. In the script: `L('English','Español')` (the English argument is the original expression, so English output never changes; the Spanish one may reorder words and handle plurals and gender). On the page: `data-es="..."` (inner HTML), `data-es-aria`, `data-es-ph`, `data-es-title`, applied once at start when `LANG==='es'`. `LANG` comes from `?lang=es` (kept in localStorage `subrotator:lang`), else the browser language; the EN/ES button in the header reloads in the other language. Dates use `LOCALE()` (es-US); `MONTHS[m].name` is the month alone for inside a sentence (lowercase in Spanish), `.long`/`.short` start with a capital. Never name a local variable `L` where text is translated (the check-in uses `ciL` for that reason). Catalog price option names have Spanish names applied at start. Release notes have `subsNoteEs`. Spanish copy: neutral Latin American Spanish, tú, reading age 8 to 9, 13 words or fewer a sentence, and the glossary in HANDOFF.md "Spanish".
- The script has marker comments: `// ==PURE-START==`..`PURE-END` (rotation planner), `CSV-START`..`CSV-END` (statement import), `EST-START`..`EST-END` (time estimator), `TV-START`..`TV-END` (TVMaze helpers; a test keeps them in step with scripts/lib/upcoming.mjs). Tests extract these blocks, so keep them free of DOM access. Anything touching the DOM goes below them.
- Design tokens are CSS variables on `:root`. Dark mode overrides live in BOTH the `prefers-color-scheme` block and `:root[data-theme="dark"]`. Keep them in sync. Fonts: Anybody (display) and Figtree (body) from Google Fonts, with fallbacks.
- Mobile first: 44px touch targets, safe-area insets, no sideways page scroll (wide content scrolls inside its own container), honor `prefers-reduced-motion`.
- Escape every user or API string with `esc()` before it goes into innerHTML.
- State is one object `{v:2, sel, H, startKey, est, hSet, keep, skip, last, country, away}` saved to localStorage key `subrotator:v1` inside try/catch. `sel` has one entry per service: catalog services keyed by family (`gamepass`, `netflix`, ...) with the plan you pay for in `tier` (and `had: true` once it was ever paid, so no new-member trial is offered; `yearly: true` when the statement shows a yearly charge), custom services keyed by their own id with `custom:true`. Each queue item may carry `tier`, the plan it needs; without one it needs the cheapest plan. `load()` migrates the old one-entry-per-plan shape. `hSet` is true once you have set your hours. `keep` marks services you chose to keep every month (the Keep button on a Cancel line): the planner prices them at 0 and their price is added to every month. `last` is this month's to-do, so the next month can ask "Did you do <Month>'s plan?" (the check-in, a card above the steps with "Update my plan" and "Not now"). It never hides the plan: steps 3 and 4 and the year chart always show (until 2026-10-21 the check-in held them back, and the owner could not find the chart). It lives in the browser like everything else, so it needs no account: only someone who comes back to the same browser in a new month sees it. `skip` is this month's taps (`{key: START_KEY, e: [service ids], up: [price-option ids]}`): `e` is Cancel or Not now on a service, `up` is Not now on an upgrade; those rows cannot be used this month, so the planner moves them later; it is dropped when the month changes. A kept price option is paid every month except when a bigger option of the same service covers it that month (no double count), and going back to it reads as a Step down. A title on a service you pay for is planned on the price option you pay for when that option covers it (`planServices`). A show can carry `air` (`[["2026-10",2],["2026-11",4]]`, episodes by the month they air, from TVMaze via `tvAir`), `ends` (the last air date) and `season`; `itemChunks` spreads its hours over those months so the plan keeps the service until the finale. A weekly season from New releases gets estimated dates from its release pattern (`releaseAir`, marked `airEst`; episodes with no date yet count one a week) until TVMaze lists every date of that same season (or a shorter season has aired); step 4 names the months with new episodes. Shows added from New releases get their `air` from `enrichAir`, which sends only the TVMaze id, once per show; a show whose hours were a guess (`hoursGuess`, also a one-tap add's first guess) gets its real total from the same lookup once the season is all listed (`tvSummary` with the item's announced `episodes`), and typed hours are never replaced. Never store statement contents.

## Non-negotiables
- Privacy: a bank or card CSV is parsed in the browser and never sent anywhere. API calls may send only title or search strings. Keep the "never uploaded" claims in the UI true.
- API keys live only in server-side env vars (`RAWG_API_KEY`, `TMDB_API_KEY`). Never in client code, git, logs, or chat.
- Honest data: prices that are estimates carry an "≈". Release dates show a "last checked" time. Credit every data source as its license requires.
- The free API tiers are non-commercial. No ads or paywalls without moving to paid plans first.

## Why it has to move to Vercel
The claude.ai artifact version (https://claude.ai/artifact/3zFPFU5S3aqmkDw61aCPEy) cannot call any outside API (its content-security policy blocks it, including a proxy). Live data needs the app hosted on Vercel with same-origin `/api/*` routes. The artifact keeps working as a static copy.
